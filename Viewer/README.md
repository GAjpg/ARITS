# LiDAR 点云工作台（独立 Mac 本地程序）

不需要 Xcode，不需要启动 iOS / Mac Catalyst App。双击本目录的 **启动点云查看器.command**，程序会打开浏览器。所有 ZIP、照片、点云和配准都在本机处理；three.js 已保存在程序内，界面不依赖外网 CDN。

## 使用

1. 将手机导出的建图 ZIP 和查询 ZIP 拖入窗口，也可点“选择文件”批量导入。
2. 左侧选择“参考地图”和“查询扫描”。可以只导入一份扫描查看点云。
3. 首次对照新数据时，点“计算整段配准”；若已有 `result.json`，也可直接拖入。地图与查询编号必须一致才会应用结果。
4. 拖动旋转、右键平移、滚轮缩放；用“空间总览 / 俯视 / 正视 / 候选相机视角”检查结构。
5. 拖动下方时间轴，查看每一帧照片、绿色点云、相机位置和朝向。方向相对于地图坐标：-Z 为 0°、+X 为 90°，不是指南针的地理北方。
6. 右侧切换候选。窄窗口时点右上角“照片 / 候选”打开检查面板。线框的顶点表示相机位置，箭头表示拍摄方向。
7. 可以启用“照片颜色”、显示采集轨迹、隐藏顶部或某层点云。照片方向可独立旋转，不改变三维计算。
8. “保存画面”导出当前三维视图 PNG；“导出定位结果”保存 JSON，之后可重新导入。

你本次提供的 1 份西口地图、5 份查询和已有配准结果已经导入当前电脑的查看器缓存。若首次打开没有显示，使用上述 ZIP 导入即可。


## 手机原始候选（新增）

支持直接导入 `geometry-map-*.zip` 轻量地图、`run-*.zip` 导航记录，或带来源信息的 `on-device-result.json`。原始查询 ZIP 中带有手机结果时也会自动读取。选择“手机记录候选（不重算）”，显示手机存下的变换与指标；不会重跑 Mac 的另一套算法来替代原结果。原始 JSON 保存在展示用封装的 `recorded_result` 中，导出再导入仍保留。

没有查询深度时标“不可重算”。旧 run 没有相机轨迹时，箭头只标示查询会话原点在地图中的映射，**不是手机当前或拍摄时的位置**；有原始查询帧时才将帧相机姿态乘以所选变换显示相机。轻量地图仅有灰度运行点云，没有原始照片、采集轨迹或颜色。

地图几何哈希或查询会话不匹配时隐藏候选叠加。搜索完整性、模式展开及原因代码直接来自结果；旧包缺这些信息时显示未知，不推测定位正确性。手动切换为旧的整段／单帧模式属于另一次 Mac 算法计算，不能拿它冒充手机结果。

新手机查询包另外保存 `solver-query.f32` 实际求解输入、精确帧号、预处理版本、算法参数和来源哈希，可由命令行回放工具重算。仅导入 run 中的一份结果不足以重算，仍需对应地图和查询输入文件。不同设备按墙钟截止时，搜索深度可能不同。

## 两种 Mac 计算模式务必区分

**整段配准 → 逐帧回放**：使用整段查询的多帧点云，求出一个查询会话到地图的变换。每帧相机位置来自 `T_地图←相机 = T_地图←查询会话 × T_查询会话←相机`。这能检查轨迹和方向，但不是每一帧单独找回了位置。

**当前帧独立定位**：只用当前帧的深度点云独立进行全局配准，不使用前后帧点云、上一帧候选或整段配准结果作为初始位置。仍会用 ARKit 提供的本帧姿态将深度放到查询会话坐标中；不是脱离 ARKit 的纯雷达 SLAM。

这个模式可以“独立计算当前帧”，也可以“逐帧计算全部查询帧”。处理在后台串行运行，可取消后续帧。尚未单独计算的帧会明确标记，不会拿整段结果冒充。单帧自身的残差没有独立留出验证，因此与整段模式的留出检查不等同。独立轨迹只连接连续有候选的帧，不跨越未计算或被拒绝的帧。

## 如何理解颜色与结果

- 蓝色：参考地图；橙色：整段查询点云；绿色：当前帧点云与选中的相机。
- 其他颜色的相机线框：同一帧的其他配准候选；选择后点云会一起变换。
- “待现场核对”：通过几何检查，未证明实际位置正确。
- “多解”：有多个相似位置，不接受唯一定位。
- “拒绝”：仍可查看诊断变换，它不能作为可靠导航位置。
- 重叠率和表面残差都不是定位精度或正确概率。

相机视角使用保存的内参和相机姿态，便于观察朝向；彩色点云从缩小后的 RGB 照片取色，仅用于显示，不参与当前几何配准。

## 数据与运行

缓存位于 `../work/pointcloud-viewer/`，包含导入 ZIP 的副本、显示用点云、逐帧缓存及配准结果。原始 Downloads ZIP 不会被修改。显示点云采用 4 像素步长、4 cm 体素、最多 22 万点；这个上限不作用于配准数据。完整原始深度仍保留在 ZIP 里。

停止程序：在启动它的终端按 Ctrl+C。关闭网页不会停止本地服务。重复双击会尽量复用已运行的查看器。默认地址是 `http://127.0.0.1:18766`，端口冲突时使用随后端口。

本机已配置好 Python 依赖。换电脑时需要 Python 3.10–3.12，先运行项目的 `Tools/setup_lidar.sh`，然后在同一虚拟环境安装 `Viewer/requirements.txt`。首次安装依赖需要联网，之后查看与计算不需要外网。

命令行启动：

```bash
../.venv/bin/python server.py
# 不自动打开浏览器：
../.venv/bin/python server.py --no-browser
```

测试：

```bash
../.venv/bin/python -m unittest discover -s . -p test_viewer.py -v
node web/test_math.mjs
```

本工具复用 `../Tools/lidar_data.py` 和 `../Tools/lidar_validate.py` 的数据校验与 FPFH/RANSAC/ICP 求解。手机采集代码没有为查看器作修改。three.js 0.180.0 的 MIT 许可见 `web/vendor/THREE-LICENSE.txt`。

## 通行空间编辑工作台（实验分支）

双击 **启动通行空间工作台.command**，或从原工作台右上角点“通行空间 · 实验”，进入 `/space`。新入口首次会编译共享 Swift 命令行工具，需要 Mac 已安装 Xcode 命令行工具；不需要打开 Xcode 或连接手机。普通点云查看入口不受影响。

当前已提供：

- 导入含 `navigation.json`、`geometry.f32` 的手机地图 ZIP，按地图编号和几何 SHA-256 分开保存工作副本；新旧补采版本可以并存。
- 二维俯视、缩放和平移、语义点定位、旧路网参考线，以及自动地面、行走证据、小洞补全、基础可走和最终可走图层。旧连线不会自动成为强制通行路径。
- 加载 `passage-calibration.json`，由手机同一套 Swift 核心校验和生成栅格；失败时保留原副本。几何哈希不同会提示，地图编号不同会拒绝。
- 显示校准矩形和未校准斜纹。矩形内白色也是最终结果；矩形外使用自动判断。建议路径作为独立覆盖层。
- 导出一个校准 JSON，原样保留已载入文件的来源和路径；没有人工栅格时导出的 `walkable` 为 null，不会把自动结果误标为已校准。手机导入是整层替换，应先确保工作台加载的是最新校准文件。

### 如何画可通行区域

1. 导入地图或选择工作副本，点击左上角 **涂绿**，按住鼠标在地图上拖动；**涂白** 把区域设为不可通行。滑块调整画笔直径。滚轮缩放，空格或右键拖动平移。
2. **撤销 / 重做** 按整笔操作；支持 ⌘Z / Ctrl+Z 和 Shift+⌘Z / Shift+Ctrl+Z。鼠标意外中断时取消当前未完成笔画。
3. **画路径** 逐点画折线，点“完成路径”或按 Enter；Esc 取消。**改路径** 可以点击紫色路径、拖动顶点。在路径面板里改宽度、插入或删除顶点、删除整条路径；这些操作也能撤销。
4. 点击 **保存校准**，保留到本机工作副本。保存后仍可撤销并再次保存；切换地图或关闭页面前会检查未保存修改。
5. 点击 **导出校准文件**，下载一个 `passage-calibration.json`，在手机地图菜单导入。可直接导出尚未保存的草稿，导出不会自动覆盖本机保存；导出前由共享 Swift 核心校验。
6. 窄窗口点画布右上角 **路径 / 预览** 打开侧栏。可在列表或图上选择起终点；修改草稿后短暂防抖，复用 Swift 核心更新路线。蓝线为路线、紫线为建议路径；不可达会显示具体原因，不会沿用旧路线。

第一次涂改以当前基础可走层为底图，整张画布成为校准范围。已有局部校准时，画笔超出原范围才扩展矩形，新包含区域取当前基础判定。紫色路径单独保存、强制可走，不烧进绿白位图；若想阻止沿紫线通行，需要删掉或移动那条路径。单纯涂白不能压过建议路径。

绿色仅表示当前可走判断，不代表已通过现场验收。障碍证据是参考图层，不会推翻人工校准。多个页面同时保存时会检查校准版本，拒绝无意覆盖；被拒绝的草稿仍可以导出。

工作副本放在 `work/pointcloud-viewer/space-projects/<map_id>-<geometry_sha256>/`；原始 ZIP 不会修改，也不向网络上传。Swift CLI 使用提取出的原始几何，不使用三维显示的降采样点云。缓存记录校准内容和工具哈希，版本变化后重新准备；若源码比工具新，需要重新执行 `bash Tools/build_space_route.sh`（双击新入口会自动处理）。

### 页面提示无法连接 / Failed to fetch

网页窗口还在，不代表本机服务仍在运行。双击“启动通行空间工作台.command”重新启动，以它打开的地址为准；正常启动方式下请保留运行服务的终端窗口。服务重启后刷新原网页，再重新选择要导入的文件。页面现在会区分连接中断、页面凭证过期和地图校验错误，不会自动重试上传。

### 点云参考、墙体画笔保护与高度辅助

通行空间工作台默认显示原始 XYZ 点云的俯视参考（离估计地面 0.4–2.6 m）；可调不透明度或显示全部高度。点云独立于绿白校准，涂改不会擦掉墙线，也不修改原始几何。投影先缓存，平移和绘制时不重复扫描全部点。

“墙体挡住画笔”默认开启：从墙内空地起笔，大画笔按点云墙线的局部遮挡裁剪，快速拖动也不能直接跨过墙线。它是编辑辅助，家具可能误挡、稀疏墙线缺口可能漏涂，必要时关闭后修正；建议路径仍按既定规则独立强制通行。

“地面高度辅助涂绿”可设置相对估计地面的上下限。先点“预览地面”看蓝色命中格，确认后点“将预览补涂为可走”。这是显式人工补涂：不替换自动规划器，不自动填补无观测大洞，不清除其他绿区；一条撤销可恢复整次补涂。地图高度漂移时可适当扩大范围，但选得过高可能把家具选入。确认后仍需保存、导出校准文件再导入手机。

新增检查：`node Viewer/web/test_space_cloud.mjs`。

### 手机开发与工作台版本隔离

工作台首次启动时把已编译的 `.build/tools/space-route` 固定到数据目录的 `space-runtime/`，附带二进制哈希；以后手机源码的修改和构建不会影响正在编辑的工作台。核心升级应在明确升级工作台时进行，不能在保存请求中隐式切换算法。缓存继续按实际二进制哈希失效。

页面凭证保存在同一数据目录的 `.viewer-token`（仅当前用户可读写），服务重启后已打开的页面可继续保存，无需为重连刷新并丢失草稿。凭证不加入地图导出。

局部地面兼容：新版核心的 `floor_field` 存在时，点云高度过滤、墙体画笔参考和高度辅助涂绿均相对所在 2 m 块的地面计算；旧栅格继续用全局高度。此兼容不会自动升级独立核心，也不会改写既有校准。

查询包兼容：帧数限制复用 `Tools/lidar_data.py`，schema 1 查询上限仍为 24，schema 2 为 64；查看器不会在第 24 帧截断新版扫描。门牌标题优先使用 `display_name`，另列原始门牌文字，旧文件仍回退 `text.raw`。
